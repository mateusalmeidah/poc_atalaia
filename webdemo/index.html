ATALAIA · UFS — Prova de Conceito 0.1

Motor de apoio à decisão LGPD / LAI

Uma camada de governança determinística, auditável e testável que reconhece sinais de dado pessoal e de interesse de transparência e encaminha conflitos para revisão humana — sem jamais tomar decisão jurídica final.

Sem LLM Sem APIs externas Apenas dados fictícios 100% no navegador

1 · O que esta PoC prova

A pergunta de pesquisa: é possível representar, de forma determinística, um fluxo mínimo de governança que reconheça sinais de dado pessoal (LGPD) e de interesse de transparência (LAI) e encaminhe situações conflitantes para revisão humana?

A contribuição está na orquestração da decisão e da evidência, não na sofisticação do classificador. Esta página reproduz, no navegador, exatamente a mesma lógica do pacote Python coberto por 38 testes automatizados.

2 · O fluxo, etapa por etapa

Cada caso percorre o mesmo caminho. As etapas acendem conforme a análise.

  1. 1

    Entrada

    Um caso sintético: id, título, descrição e metadados.

  2. 2

    Detecção de PII

    Regex para CPF, e-mail, telefone e marcador de nome.

  3. 3

    Detecção de LAI

    Taxonomia de palavras-chave de transparência.

  4. 4

    Regra de decisão

    Tabela determinística → recomendação de fluxo.

  5. 5

    Escalada humana

    Conflito PII + LAI ⇒ sempre escala (fail-safe).

  6. 6

    GOV-ADR

    Evidência em Markdown com decisão humana PENDENTE.

6 · Stack e restrições

      

        A simplicidade aqui é um recurso, não uma limitação. O
        motor foi mantido determinístico e sem “caixa-preta” de propósito: quanto
        menos mágica, mais confiável a evidência e a auditoria.
      


      

        

          
O que usamos

          
    
            
  • Python + biblioteca padrão (re,
              json, dataclasses, datetime,
              pathlib) — o motor, núcleo da PoC.
    • 
            
  • pytest — única dependência, e só para rodar os
              38 testes; não faz parte do produto.
    • 
            
  • HTML, CSS e JavaScript puro — esta vitrine, sem
              nenhum framework de front-end.
    • 
            
  • Git / GitHub + GitHub Pages — versionamento e
              hospedagem do link público.
    • 
          

        


        

          
O que NÃO usamos (de propósito)

          
    
            
  • Nenhum LLM / IA — nada de modelos de linguagem.
    • 
            
  • Nenhuma API externa ou nuvem no motor.
    • 
            
  • Nenhum banco de dados.
    • 
            
  • Nenhuma biblioteca de PII/anonimização
              (Presidio, ARX, AMNESIA, scrubadub).
    • 
            
  • Nenhum dado real — apenas fictícios.
    • 
          

        

      


      

        Por quê? A PoC prova o fluxo de governança e evidência de
        forma determinística: a mesma entrada produz sempre o mesmo resultado. Um
        LLM ou serviço externo poderia variar a resposta — o oposto do que uma
        trilha de auditoria precisa. No núcleo, usamos só a linguagem e o
        essencial.
      

    


    
    

      
7 · Próximos passos (PoC 0.2)

      

        A PoC 0.1 provou o fluxo de governança com um detector
        mínimo. A próxima etapa testa se a mesma camada de governança sustenta
        ferramentas mais robustas por baixo — mantendo tudo determinístico e
        auditável — e fecha o ciclo da decisão humana.
      


      
    
        
  1. 
          foco principal
          
    Detector profissional sob a camada de governança
    
          
    
            Avaliar uma biblioteca madura de PII (ex.: Presidio) como motor de
            detecção, mantendo a nossa lógica determinística como a camada que
            decide o encaminhamento. Prova que o valor está na
            orquestração, não no detector.
          
    
        
    2. 
        
  2. 
          evidência
          
    Fechar o ciclo da decisão humana
    
          
    
            Hoje todo GOV-ADR nasce PENDENTE. A 0.2 registra quando um
            humano decidiu (aprovou, restringiu etc.), criando uma trilha
            completa de “quem decidiu o quê e quando”.
          
    
        
    3. 
        
  3. 
          detecção
          
    PII mais robusta
    
          
    
            Validação de dígito verificador do CPF e novos tipos de dado pessoal
            (RG, CNPJ, data de nascimento), reduzindo falsos positivos.
          
    
        
    4. 
        
  4. 
          configuração
          
    Taxonomia de transparência externa
    
          
    
            Mover as palavras-chave de LAI do código para um arquivo de regras,
            permitindo que especialistas ajustem sem programar.
          
    
        
    5. 
        
  5. 
          escala
          
    Relatório agregado de múltiplos casos
    
          
    
            Processar lotes e gerar um panorama (quantos escalaram, quantos
            neutros etc.), além da análise caso a caso.
          
    
        
    6. 
      


      

        Princípio mantido em todas as etapas: na dúvida, escalar para
        humano (fail-safe). A máquina acelera e organiza; a pessoa decide.
